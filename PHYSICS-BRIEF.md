# Build Brief — HSC **Physics**

**Hand this entire file to another agent.** It is a complete, self-contained specification:
what to build, how to build it, the two things this project has repeatedly got wrong
(question accuracy and notation alignment), and the defects three sibling apps already paid
for so you don't repeat them.

The reference implementation is **MoleQuest**, a game-based HSC Chemistry study app:
<https://github.com/TheFinster2/Study-App> (branch `claude/hsc-chemistry-study-app-04o2ri`).
Clone and play it before writing any code — it is ~10,000 lines across 45 files with no
build step, so it reads end to end in one sitting.

**Also read, in this order, before you design anything:**
1. `MATHS-BRIEF-STANDARD.md` §2, §3, §8, §9 — architecture and the first twelve defects.
2. `MATHS-BRIEF-STANDARD-ADDENDUM.md` — *all of it*. Nine more defects and the testing
   discipline that found them. It is short and every item cost real time to learn.

**Working name:** *Newton's Notebook*. Change it if you have a better one.

Two things in this brief are non-negotiable because they are exactly what the earlier apps
got wrong:

- **§5 — question accuracy and uniqueness.** Physics questions are computed, not written.
  A generator that is subtly wrong produces hundreds of confidently wrong questions, which
  is worse than having none.
- **§6 — notation alignment.** The maths apps shipped fractions whose bar sat below the
  baseline and superscripts that made line spacing ragged. §6 gives you measured,
  working CSS. Use it verbatim.

---

## 1. What you are building

A zero-dependency, offline-first PWA that makes NSW HSC Physics revision feel like a game.
Eleven-ish modes, levels, a currency, boss fights, spaced-repetition flashcards, an arcade
you *spend* the currency on, and a reference sheet. One student, one phone, a whole HSC year.

**Constraints, all non-negotiable:**

- No build step, no bundler, no npm dependencies at runtime. Classic `<script>` tags in
  dependency order so it runs from `file://` as well as over HTTP.
- One global, `window.PHYS` (chemistry uses `CHEM`). Every module hangs off it.
- No network at runtime. No accounts. No analytics. No AI at runtime — every question is
  either authored or generated by deterministic code you ship.
- Works offline from the second launch (service worker, precached).
- Mobile first. 360 px wide is the design target, not an afterthought.

## 2. Architecture to copy

Read `MATHS-BRIEF-STANDARD.md` §3 for the full description. The short version:

```
index.html          script tags in dependency order, nothing else
css/styles.css      one stylesheet, CSS custom properties for themes
js/core/util.js     DOM helper, sampling, formatting, the notation renderer (§6)
js/core/state.js    save/load, XP, levels, streaks, achievements
js/core/ui.js       hash router, modals, toasts, gameShell, award()
js/core/bank.js     question discovery, weighting, draw
js/core/units.js    the units engine (§5.3) — physics-specific, chemistry has no equivalent
js/data/*.js        content only, no logic
js/games/*.js       one file per mode
js/screens/*.js     one file per screen
sw.js               precache list + cache-first fetch
```

**The two conventions that hold it together:**

1. **Every reward flows through `UI.award({xp, coins, bonus, accuracy})`.** Nothing else
   touches XP or currency. This is what makes "the arcade pays nothing" a structural fact
   rather than a promise — the arcade simply never calls it.
2. **Content is discovered, not listed.** `Bank.all()` scans `PHYS.DATA` for keys matching a
   pattern rather than concatenating a hand-written list. A hand-written list silently lost
   87 flashcards in the chemistry app when a new file sorted before the file that declared
   the array. See the addendum, D4.

## 3. Content — NSW HSC Physics

Eight modules. Year 12 (5–8) is what gets examined, so weight the bank towards it.

| | Module | Core topics |
|---|---|---|
| **Y11** | 1. Kinematics | motion in a straight line, graphs, relative motion, vectors |
| | 2. Dynamics | forces, Newton's laws, momentum, impulse, work, energy, collisions |
| | 3. Waves and Thermodynamics | wave properties, sound, ray model of light, thermodynamics |
| | 4. Electricity and Magnetism | electrostatics, circuits, magnetism |
| **Y12** | 5. Advanced Mechanics | projectiles, circular motion, gravitation, orbits, Kepler |
| | 6. Electromagnetism | motors, EM induction, Lenz's/Faraday's law, generators, transformers |
| | 7. The Nature of Light | EM spectrum, spectroscopy, photoelectric effect, special relativity |
| | 8. From the Universe to the Atom | stars, Bohr/quantum models, nuclear physics, the Standard Model |

### 3.1 Volume targets

Match the chemistry app's density. It ended at 944 questions and 263 flashcards.

| | target |
|---|---|
| Authored multiple-choice | **120–180 per Year 12 module, 80–120 per Year 11 module** (~1,000 total) |
| Generator templates | **60–90**, each producing an unbounded family (§5) |
| Flashcards | **250–350** |
| Worked examples in the reference section | 40+ |

**Authored and generated questions are different things and need different validation.**
Authored ones get the length-bias and duplicate checks (§5.6). Generated ones get
correctness-by-construction plus dimensional analysis (§5.2–5.4). Do not treat them as one
pile.

### 3.2 The data sheet is the source of truth for every constant

NESA gives students a data sheet, formula sheet and periodic table in the exam. **Your
constants must be the data sheet's values, to the data sheet's precision** — if the sheet
says `g = 9.8 m s⁻²` and you compute with 9.81, your answer disagrees with the student's
correct working and you have taught them they are wrong.

Put every constant in one file, `js/data/constants.js`, each with its symbol, value, units
and a source note. **Fetch the current NESA Physics data sheet and copy the values from it —
do not take them from this brief, from memory, or from a general-purpose reference.** Values
drift between syllabus versions and precision differs (the sheet's `G = 6.67 × 10⁻¹¹` is
three significant figures, not the CODATA value). One wrong constant silently corrupts every
question that touches it.

Then write a test that asserts every generator draws its constants from that file rather
than inlining a literal. A grep for suspicious numeric literals (`9\.8|3\.00?e8|6\.67`) in
`js/data/generators/*.js` is enough and takes five minutes.

## 4. Game modes

Copy the chemistry app's shell and swap the content. The mapping:

| Chemistry | Physics | Notes |
|---|---|---|
| Rapid Fire | **Rapid Fire** | 2 min, endless MCQ, streak multiplier to ×3 |
| Module Drill | **Module Drill** | 15 adaptive questions from one module |
| Balance Blitz | **Free-Body Builder** | drag forces onto a body, get magnitudes and directions right |
| Ion Memory | **Formula Match** | match quantity ↔ formula ↔ SI unit (three-way, harder than pairs) |
| Name That Compound | **Graph Story** | match a motion graph to its description, and the reverse |
| Calculation Crunch | **Calculation Crunch** | the generator engine of §5 — your highest-value mode |
| Precipitation Panic | **Unit Grid** | fill a grid of quantity × unit against the clock |
| Titration Lab | **Circuit Bench** | build/measure a circuit, then compute an unknown |
| Pathway Puzzle | **Derivation Chain** | reach a target quantity from givens by choosing equations |
| Survival | **Survival** | one life, tightening clock |
| Mistake Rehab | **Mistake Rehab** | only what you've previously missed |

Two of these deserve specific comment.

**Derivation Chain** is the direct analogue of chemistry's Pathway Puzzle, and it is the best
physics mode in this list: give the student `u`, `a`, `t` and ask for `s`; they pick
equations from the formula sheet one at a time and each pick either applies (because its
unknowns are now all known) or doesn't. It teaches equation selection, which is the actual
exam skill. **Read the addendum §C1 and §C2 before building it** — the chemistry version
shipped two farming holes (a per-item score floor, and a restart button that acted as a free
undo) and both apply here unchanged.

**Free-Body Builder** replaces Balance Blitz. Its optional "show the resultant" helper is a
genuine crutch, so it must cost XP and **latch** — see addendum §C3.

### The Arcade

Three games you rent by the minute with the currency. **They pay nothing.** No XP, no
currency, no achievements — only a high score. An arcade game that paid XP would immediately
become a better XP-per-minute rate than studying, which defeats the entire app. It is a
*sink*, and the guarantee is structural: arcade code never calls `UI.award`.

## 5. Making questions that are unique **and** accurate

This is the section that matters most. Read it twice.

### 5.1 The generator contract: answer first, question second

Never write a question and then work out the answer. **Pick the answer, then construct a
scenario that produces it.** Chemistry learned this the hard way (`MATHS-BRIEF-STANDARD.md`
§9.9) and physics is worse, because a plausible-looking scenario can be physically
impossible in ways that only show up in the arithmetic.

Every generator is a function returning a fully-formed, self-describing question:

```js
{
  id: "gen-m5-proj-042",        // template id + seed, so it is reproducible
  template: "projectile-range",  // for uniqueness accounting (§5.5)
  mod: "M5", topic: "Projectile motion", diff: 2,
  givens: { u: 25, theta: 35, h: 0 },
  q: "A ball is launched at 25 m s^-1 at 35 deg above the horizontal from ground level. …",
  answer: { value: 59.9, units: { m: 1 }, sigFig: 3 },
  tolerance: 0.02,               // fractional
  working: [ … ],                // the steps, rendered on the results screen
  distractors: [ … ]             // §5.4
}
```

### 5.2 Verify every generated answer by a second, independent route

One computation can be wrong in a way no amount of re-reading reveals. Two computations that
agree are strong evidence. For every template, compute the answer twice by genuinely
different physics and assert they match:

| Template family | Route A | Route B |
|---|---|---|
| Projectile range | kinematics, solve for flight time | energy + symmetry of the trajectory |
| Final speed down a ramp | `v² = u² + 2as` | conservation of energy |
| Orbital period | Kepler's third law | equate gravitational force to centripetal force |
| Collision outcome | conservation of momentum | conservation of kinetic energy (elastic only) |
| Transformer secondary voltage | turns ratio | power conservation with the stated efficiency |
| Photoelectric stopping voltage | `eV = hf − φ` | energy balance from threshold frequency |

Where a second physical route genuinely doesn't exist (`E = mc²`), verify by **inverting**:
take the answer, recompute one of the givens from it, and assert you get the original back.

Run this over **every template × 200 random seeds** in the validator. It is fast, it is
exhaustive, and it is the single highest-value test in the project. The chemistry equivalent
(re-balancing every stored equation from its parsed formulas) caught real errors.

### 5.3 A units engine, and dimensional analysis on every question

Represent a quantity as `{ value, units: { kg: 1, m: 2, s: -2 } }`. Roughly 80 lines gives
you multiply, divide, power, add (asserting the maps match), and a formatter. Then:

- **Every generated answer's dimensions must match what the question asks for.** If the stem
  says "find the kinetic energy" the answer's map must be `{kg:1, m:2, s:-2}`. This catches
  an entire class of generator bug — a dropped square, a divide that should be a multiply —
  automatically, on every seed, forever.
- It powers the **Unit Grid** mode and live dimensional-analysis feedback.
- It lets you accept student answers in any consistent unit (`km h⁻¹` where you computed
  `m s⁻¹`).

### 5.4 Distractors must be named misconceptions, not noise

`answer × 2` and `answer ÷ 2` are lazy and a student learns nothing from ruling them out.
Every distractor should be **the answer you get by making one specific, common mistake**, and
the question should record which one:

```js
distractors: [
  { value: 42.7, why: "used sin instead of cos to resolve the horizontal component" },
  { value: 30.6, why: "forgot the factor of 2 in the range formula" },
  { value: 63.8, why: "used g = 10 rather than the data sheet's 9.8" }
]
```

Three payoffs: the feedback screen can name the mistake ("you resolved with sin θ — the
*horizontal* component is u cos θ"), Mistake Rehab can target it, and — because each
distractor is computed — you cannot accidentally generate a distractor equal to the correct
answer. **Assert that.** Also assert no two distractors collide after rounding, which
happens more than you'd think at 2 significant figures.

Build a catalogue of physics misconceptions per topic and reuse it: sin/cos swap, `g` sign
errors, mass vs weight, speed vs velocity, forgetting a factor of ½, radius vs diameter,
degrees vs radians, per-mole vs per-particle, using the wrong reference frame, treating
`v_avg` as `(v₁+v₂)/2` when acceleration isn't uniform.

### 5.5 Uniqueness: check **templates**, not rendered text

This is the trap specific to generated banks. Bigram duplicate detection (addendum D2) run
over rendered question text will happily pass 200 questions that are all
"a *m* kg mass on a *θ*° incline" with different numbers, because the numbers differ. You end
up with a huge bank that feels like ten questions.

Do both checks:

1. **Normalise then compare, for near-duplicate detection.** Replace every numeral with `#`
   and every unit with its dimension before hashing. Two questions with the same normalised
   form are *the same question* regardless of their numbers.
2. **Enforce template diversity per topic.** No single template may supply more than ~25% of
   a topic's questions in a session's draw. Track it in `Bank.draw` and in the validator.

And keep the authored-question checks from the addendum:
- Bigram Jaccard > 0.75 between stems within a topic = duplicate. **Bigrams, not unigrams** —
  "the current increases" and "the current decreases" share every word.
- Keep digits, operators and symbols in the tokens. Stripping them collapsed
  `ΔH < 0 and ΔS > 0` and its opposite into the same token set in the chemistry app.

### 5.6 Answer-length bias — the defect the student found, not the tests

Writing options as mini-explanations makes the correct one the longest, and a student who
always picks the longest option scores about 64% while knowing nothing. Rewrite until the key
is strictly longest in **no more than about 25%** of questions — the chance rate for four
options — and have the validator fail the build above 32% overall **or 36% in any single
module**. The per-module limit matters: a healthy 24% overall average in the chemistry app
was hiding one module at 38%.

Generated questions are not exempt. If your distractors are computed and the correct answer
is formatted differently (more decimal places, a unit spelled out), you have re-created the
tell numerically. Format every option identically.

### 5.7 Significant figures and tolerance

Physics marking is not exact-match. Decide once, centrally:

- Accept within a **fractional tolerance** (2% is a reasonable default), not an absolute one.
- Accept the answer in any dimensionally-equivalent unit (§5.3).
- Show the expected value to the data sheet's precision in the feedback, and state the
  tolerance so the student knows why they were marked right.
- Never mark on significant figures *silently*. If you want to teach sig figs, make it an
  explicit mode with its own feedback, not a hidden reason for a red cross.

## 6. Notation: symbols, fractions and alignment

**The maths apps got this wrong and it is visible on every screen.** The brief they were
given said to build fractions with `display: inline-flex; flex-direction: column` and a
`border-top` on the denominator. That baseline-aligns the fraction by the *bottom* of the
block, so the bar sits well below the surrounding text. Measured in Chromium at 17 px:
**the bar lands 13.7 px below the maths axis — about 1.5× the x-height.** It looks broken
because it is.

Everything below is measured, not asserted. Copy it verbatim.

**A working fixture ships with this brief:** open `docs/notation-reference.html` in a
browser to see the broken version and the fixed version side by side, and run
`docs/notation-test.js` (Playwright) for the numbers. Both are the source the CSS below was
copied from.

### 6.1 The rules

1. **A fraction is a two-row `inline-grid` with `vertical-align: middle`.**
   CSS defines `middle` as *baseline + half the parent's x-height* — which is the maths axis
   by definition. If the fraction's own vertical midpoint is the bar, the bar lands exactly
   on the axis, in any font, at any size, with no magic offset. Measured offset: **0.01 px.**
   Keep the padding above and below the bar symmetric, or the midpoint drifts off it.

2. **Superscripts and subscripts use `position: relative`, never `vertical-align: super/sub`.**
   The keywords grow the line box, so a line containing `v²` becomes taller than one without
   it and paragraphs go ragged — and a question card visibly jumps when the next question has
   a different number of exponents. With `position: relative` the line height is *identical*:
   measured 43.05 px with and without.

3. **Simultaneous sub + superscript** (nuclear notation, `²³⁵₉₂U`) is its own two-row grid,
   right-aligned against the symbol. Measured edge alignment: **0.00 px.**

4. **The radical is an SVG, not the `√` glyph.** A glyph is a fixed size; over a fraction it
   sits at the bottom while the overline starts in mid-air above it. An SVG with
   `preserveAspectRatio="none"` stretches to the content. Two traps, both hit while building
   this: the body must be its own **box** (`display:flex`) or the overline is drawn at the
   line-box top and **strikes through** anything tall underneath it; and the SVG must be
   **absolutely positioned** inside the stretched box, because `height: 100%` against an
   auto-height parent is indeterminate and Chromium falls back to the SVG default of 150 px,
   giving you a radical that towers over the line.

5. **Do not pull in KaTeX or MathJax.** 300 kB, a font-file precache problem, and a
   flash-of-unstyled-maths on every question. Everything HSC Physics needs is above.

### 6.2 The CSS — verified, copy as-is

```css
/* A fraction's vertical midpoint IS the bar, so `vertical-align:middle` lands the bar
   on the maths axis. Keep the padding symmetric or the midpoint drifts off it. */
.frac{
  display:inline-grid; grid-template-rows:1fr 1fr; justify-items:center;
  vertical-align:middle; font-size:.94em; line-height:1.12; text-align:center;
}
.frac > .num{ padding:0 .22em .06em; }
.frac > .den{ padding:.06em .22em 0; border-top:.075em solid currentColor; }

/* position:relative, NOT vertical-align:super — the keywords grow the line box. */
.sup, .sub{ font-size:.72em; position:relative; line-height:0; }
.sup{ top:-.46em; }
.sub{ top: .26em; }

/* Simultaneous sub+super, e.g. nuclear notation. */
.updown{
  display:inline-grid; grid-template-rows:1fr 1fr; justify-items:end;
  vertical-align:middle; font-size:.7em; line-height:1.05; margin-right:.06em;
}

/* Vector arrow that scales with the glyph and never collides with it. */
.vec{ position:relative; white-space:nowrap; }
.vec::after{
  content:"→"; position:absolute; left:50%; transform:translateX(-50%);
  top:-.72em; font-size:.62em; line-height:1; pointer-events:none;
}

/* Square root. The body is its own box so the overline clears tall content; the
   radical is a stretchable SVG, absolutely positioned so its height is definite. */
.sqrt{ display:inline-flex; align-items:stretch; vertical-align:middle; white-space:nowrap; }
.sqrt > .rad{ position:relative; width:.6em; align-self:stretch; }
.sqrt > .rad svg{ position:absolute; inset:0; width:100%; height:100%; }
.sqrt > .body{
  border-top:.07em solid currentColor; padding:.14em .2em 0 .08em;
  display:flex; align-items:center;
}

.unit{ white-space:nowrap; }   /* never break "m s⁻²" across a line */
```

The radical markup:

```html
<span class="sqrt">
  <span class="rad"><svg viewBox="0 0 12 100" preserveAspectRatio="none" aria-hidden="true">
    <path d="M0.5,62 L4,56 L7,95 L11.5,3" fill="none" stroke="currentColor"
          stroke-width="4" vector-effect="non-scaling-stroke"
          stroke-linecap="round" stroke-linejoin="round"/>
  </svg></span>
  <span class="body">…</span>
</span>
```

`vector-effect="non-scaling-stroke"` keeps the stroke weight constant as the SVG stretches —
without it the radical gets fatter as it gets taller.

### 6.3 The source syntax

Content files should never contain HTML. Write a renderer in `util.js` that turns a compact
syntax into the markup above, escaping HTML **first**:

| You write | Renders |
|---|---|
| `v^2`, `s^-1` | superscript |
| `E_k`, `m_1` | subscript |
| `\f{Δx}{Δt}` | built-up fraction |
| `\sqrt{u^2 + 2as}` | radical |
| `\nuc{235}{92}U` | ²³⁵₉₂U |
| `\v{F} = m\v{a}` | vector arrows |
| `\u{m s^-2}` | non-breaking unit |
| `Delta`, `lambda`, `omega`, `mu`, `theta` | Δ λ ω μ θ |

Escape before substituting, in that order, or you have built an XSS hole into a study app.

### 6.4 Keep the alignment test

This is a real regression test, not a nicety — the failure mode is silent and only visible if
someone looks. It measures rather than eyeballs:

- **Fraction bar vs the maths axis.** Append a zero-width probe span of `height: 1ex` and
  `vertical-align: baseline` to the line, read its rect: `bottom` is the baseline, `height`
  is the x-height, so the axis is `bottom − height/2`. Assert the denominator's `top` (which
  is the bar) is within 12% of the x-height of it.
- **Line-box disturbance.** Two otherwise identical lines, one containing superscripts.
  Assert the heights are equal to within 0.5 px.
- **Nuclear stack.** Assert the two rows' right edges differ by < 0.5 px.
- **Radical.** Assert the drawn SVG's top meets the overline, and that its height is within
  5% of the body's — **in both directions.** Checking only "not too short" passes a radical
  that has blown up to 150 px, which is exactly what happened while writing this.

Keep a rendered screenshot of the full sample in the repo and look at it after any change to
the stylesheet. The 150 px radical passed every numeric assertion at the time; the picture
is what showed it.

## 7. Diagrams

Physics needs more drawing than chemistry did and about as much as maths. Write one
`js/core/draw.js` with a consistent API and reuse it across questions, games and the
reference screens:

- motion graphs (x–t, v–t, a–t) with shaded areas
- free-body diagrams: a body plus labelled force arrows at angles
- projectile trajectories with velocity components at a marked instant
- ray diagrams for lenses and mirrors
- circuit schematics (series/parallel, cells, resistors, meters, switches)
- field diagrams: radial, uniform, and around a current-carrying wire
- wave snapshots with wavelength and amplitude marked
- energy-level diagrams for the Bohr model

Read theme colours from CSS custom properties inside the draw functions so diagrams follow
the active theme. Every diagram must be legible at 360 px — test it, don't assume it.

## 8. Progression and economy

Copy the chemistry app's tuned numbers rather than inventing your own; they represent a
year's worth of adjustment and one round of explicit rebalancing.

| | value |
|---|---|
| XP per correct answer | `10 × difficulty`, × streak multiplier (×1 → ×3 in half steps every 5 correct) |
| Level *n* cost | `round(115 × n^1.5)` XP, 60 levels |
| Reaching Lv 20 / Lv 60 | ~77,000 / ~1.26 M XP total |
| Currency payout | run value × **0.75** |
| Cheapest arcade ticket | ~315 for 5 minutes |
| Completion bonus | withheld entirely below 50% accuracy |
| Minimum read time | 1.2 s — faster than that earns nothing |

unscaled and will drown your measurement if you don't silence them.

## 9. Testing regime — build these as you go

Nine standalone Playwright/Node scripts. Do not retrofit them; they are much cheaper written
alongside the thing they cover.

1. **`validate.js`** — content integrity, no browser needed. Counts; unique IDs; 4 options;
   answer index in range; no duplicate options; metadata present. Then the physics-specific
   half: **every generator × 200 seeds**, each answer verified by a second route (§5.2), each
   answer dimensionally checked (§5.3), each distractor distinct from the key and from each
   other after rounding, template-normalised duplicate check (§5.5), per-module answer-length
   bias (§5.6), and every constant traced to `constants.js`.
2. **`smoke.js`** — every screen and every mode driven end to end. Zero console errors. No
   horizontal overflow at 360 px and 390 px. Button hover states don't repaint primaries.
3. **`notation.js`** — §6.4. Measured alignment, plus a screenshot.
4. **`exploit.js`** — a bot that plays every mode badly and reports XP/hour. Target 0.
5. **`honest.js`** — a bot that plays every mode well. Should be comfortably higher, and
   roughly consistent across modes.
6. **`helpers.js`** — turn each optional crutch on then off; assert the penalty survives.
7. **`offline.js`** — install, go offline, assert every screen renders and progress persists.
8. **`update.js`** — deploy a new version; assert it is detected while open **and** applied
   on next launch. Run with `BREAK=1` to confirm it still fails without the fix.
9. **`import.js`** — export, mutate, import, reload, assert the imported values are live.

**And the habit that matters more than any of them: prove each test fails without its fix.**
Addendum §A. It caught three tests in the chemistry app that were passing while testing
nothing at all.

## 10. The defects you are inheriting — a checklist

Every one of these is in the two maths documents with full detail. Skim this list now and
read the detail when you reach the relevant code.

**Silent-failure class (you won't notice these without a test):**
- Hand-listed content silently dropped 87 cards. Discover, don't list. *(Addendum D4)*
- A cache version not bumped means your fix never reaches an installed phone. *(E1)*
- An import destroyed itself: `location.reload()` → `pagehide` → flush → the old in-memory
  save overwrote the imported file. *(F1)*
- Unigram duplicate detection passes exact opposites. *(D2)*
- A per-module bias limit is needed; the overall average hides outliers. *(D1)*

**Farming class (a student will find these; ours did):**
- Per-item score floors. *(C1)*
- Restart buttons that reset the cost counter. *(C2)*
- Optional helpers that refund their penalty when switched off. *(C3)*
- Randomly generated boards that come up trivially uniform. *(C4)*

**Service worker class (this generated the most support questions of anything):**
- `updatefound` never fires for an already-waiting worker. *(E2)*
- Calling `update()` when one is already waiting makes Chromium reinstall it and downgrades
  a silent apply into a dismissable prompt — the "updates take forever" symptom. *(E3)*
- iOS does not clear website data when a home-screen PWA is deleted; ship a Force refresh
  and show the running build. *(E6)*

**Layout and rendering class:**
- Fractions and superscripts — §6 of this brief.
- `display:grid` beats the `hidden` attribute; add `[hidden]{display:none !important}`.
  *(Maths brief §9.1)*
- Grid/flex children default to `min-width:auto` and overflow on mobile. *(§9.2)*
- A hover rule that repeats a base value still outranks `.btn-primary` → dark on dark.
  *(Addendum H2)*
- Sticky elements must clear fixed chrome; publish the bar height as a CSS variable. *(H3)*

**UX class:**
- Never open a results overlay over an explanation the student is reading. Gate it behind a
  button and provide a way back. *(H1)* Physics worked solutions are long — this matters more
  here than it did in chemistry.

## 11. Build order

1. Shell: `index.html`, `util.js` (**including §6 notation and its test — do this first, it
   is in every screen you build afterwards**), `state.js`, `ui.js`, router, one screen.
2. `constants.js` from the NESA data sheet, and `units.js`.
3. `bank.js` and 60–80 authored questions across two modules. Get `validate.js` green.
4. Rapid Fire and Module Drill. Get `smoke.js` green.
5. The generator engine and the first 10 templates, with §5.2 verification from the start.
6. `draw.js` and the diagram-dependent modes.
7. Remaining modes, then bosses, flashcards, shop, achievements.
8. Service worker, offline test, update test.
9. The arcade — last, because it is the least important and the most fun to over-build.
10. Fill the content banks to the §3.1 targets.

Ship something playable at step 4 and keep it playable. The chemistry app was usable from
about day one and every feature landed on a working thing.

## 12. Tone

The student using this is doing the HSC. It should feel like a game they *want* to open, not
homework with points bolted on: fast transitions, sound that isn't annoying, a level-up that
feels earned, explanations that read like a good teacher rather than a mark scheme. Every
wrong answer is a teaching moment — say what the misconception was, not just what the answer
was (§5.4 gives you that for free).

And it must be *honest*. If it says a run is worth 200 XP, that must be what a student who
knows the physics earns, and a student who knows nothing must earn zero. The whole thing
falls apart the moment clicking beats studying.
