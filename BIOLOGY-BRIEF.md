**Hand this entire file to another agent.** It is a complete, self-contained specification.

The reference implementation is **MoleQuest**, a game-based HSC Chemistry study app:
<https://github.com/TheFinster2/Study-App> (branch `claude/hsc-chemistry-study-app-04o2ri`).
Clone and play it before writing any code — ~12,000 lines across 50 files, no build step, so

## 0. Biology is not chemistry with different words — read this before designing

Every previous app in this family was built around a *right answer you can compute*.
Biology mostly isn't. Three consequences shape the whole build:

**The core skill is written explanation, not calculation.** An HSC Biology paper is
dominated by "explain", "compare", "assess" and "justify". A multiple-choice-only app
trains the wrong thing. §4 is the most important section here.

**Diagrams are content, not decoration.** Label a nephron, read a pedigree, interpret a
transect, sequence the immune response. In chemistry the diagrams supported the questions;
in biology they frequently *are* the questions. §3 is the biggest build item and you should
start it on day one.

**Genetics is the one genuinely computable part**, and it is the best game in the subject.
Punnett squares, pedigrees, ratios and probabilities are exactly generatable and exactly
checkable. Treat it the way the physics brief treats its generators — answer first, verified
by a second route. §5.

There is a fourth difference worth knowing before you price anything: **NSW Biology gives
students no formula or data sheet in the exam.** Confirm that against the current NESA exam
papers rather than taking my word for it, because it decides how you price the in-app
reference (§7).

## 1. What you are building

A zero-dependency, offline-first PWA that makes NSW HSC Biology revision feel like a game.
Eleven-ish modes, levels, a currency, boss fights, spaced-repetition flashcards, an arcade
you *spend* the currency on, and a reference section. One student, one phone, a whole year.

**Constraints, all non-negotiable:**

- No build step, no bundler, no npm dependency at runtime. Classic `<script>` tags in
  dependency order, so it runs from `file://` as well as over HTTP.
- One global, `window.BIO`. Every module hangs off it.
- No network at runtime. No accounts. No analytics. **No AI at runtime** — every question is
  authored or generated by deterministic code you ship.
- Works offline from the second launch.
- Mobile first. 360 px is the design target, not an afterthought.

## 2. Architecture to copy

`MATHS-BRIEF-STANDARD.md` §3 has the full description. The biology-specific additions:

```
js/core/util.js      DOM helpers, sampling, formatting, the expression evaluator
js/core/state.js     save/load, XP, levels, streaks, achievements, coverage toggles
js/core/ui.js        hash router, modals, gameShell, award()
js/core/tools.js     the in-game tool tray (§7)
js/core/bank.js      question discovery, coverage filtering, adaptive draw
js/core/diagram.js   the SVG label/hotspot engine — biology-specific, §3
js/core/genetics.js  crosses, Punnett squares, pedigree inference — biology-specific, §5
js/core/mark.js      short-answer self-marking, §4
js/data/*.js         content only, no logic
js/data/diagrams/*.js one file per diagram, §3.2
```

**The three conventions that hold it together:**

1. **Every reward flows through `UI.award({xp, coins, bonus, accuracy})`.** Nothing else
   touches XP or currency. That is what makes "the arcade pays nothing" and "the reference
   costs 20%" structural facts rather than promises.
2. **Content is discovered, not listed.** `Bank.all()` scans `BIO.DATA` for keys matching a
   pattern. A hand-written list silently lost 87 flashcards in the chemistry app when a new
   file sorted before the one that declared the array. (Addendum D4.)
3. **The complete bank and the active bank are different functions.** `all()` is everything
   — achievement targets and totals measure against it. `active()` is what gets asked after
   the coverage toggles in §8. Mixing them up lets a student shorten a collection by hiding
   content.

## 3. Diagrams — start here, it is the biggest item

### 3.1 What you need

Label, identify or sequence:

- animal and plant cells, and the organelles
- the fluid mosaic membrane; osmosis and diffusion set-ups
- DNA structure, replication, transcription and translation
- mitosis and meiosis stages, including crossing over
- pedigree charts (§5)
- the heart, a nephron, an alveolus, a leaf cross-section, a stoma
- a neuron, a synapse, a reflex arc
- the three lines of defence, antigen presentation, antibody structure
- food webs, energy pyramids, transects and quadrats
- epidemiological curves and dose-response graphs

### 3.2 The engine

One `js/core/diagram.js` plus one data file per diagram. A diagram is **inline SVG you
author by hand** with `id`s on the labellable parts:

```js
BIO.DATA.diagrams.animalCell = {
  id: "animalCell", title: "Animal cell", mod: "M1",
  svg: "<svg viewBox='0 0 400 300'>…<ellipse id='nucleus' …/>…</svg>",
  parts: [
    { id: "nucleus", label: "Nucleus",
      role: "Contains the DNA and controls the cell's activities",
      accept: ["nucleus"] },
    { id: "mitochondrion", label: "Mitochondrion",
      role: "Site of aerobic respiration; releases ATP",
      accept: ["mitochondrion", "mitochondria"] }
  ]
};
```

The engine gives you, from that one definition: **label the diagram** (drag or tap-then-tap),
**identify the part** (highlight one, name it), **state the function** (highlight one, pick
the role), and a **static reference view**. Four modes from one authoring effort — which is
what makes hand-authoring forty diagrams worth doing.

Read theme colours from CSS custom properties inside the SVG (`fill="var(--card-2)"`,
`stroke="var(--line)"`) so diagrams follow the active theme.

### 3.3 Things that will bite you

- **Touch targets.** A `<path>` for the Golgi is an awkward shape to hit. Give every
  labellable part an invisible `<circle>` hit area of at least 44 px and put the listener on
  that, not on the artwork.
- **Labels must not overlap the artwork at 360 px.** Put the label bank *below* the diagram
  in a wrapping row, not floating over it. Test it, don't assume — the addendum's H6 check
  (no horizontal overflow at 360/390 px) belongs in your smoke test from day one.
- **`viewBox` and nothing else.** No fixed width/height on the SVG; let CSS size it with
  `width:100%; height:auto`. Anything else breaks on rotation.
- **A diagram with N parts is not N questions.** Draw a subset per round and shuffle which
  parts are asked, or the mode becomes memorisation of a fixed order.

## 4. Short answer and extended response — the honesty rule

This is the section that decides whether the app is respected or resented.

### 4.1 Never claim to mark prose

`ENGLISH-BRIEF-ADVANCED.md` §0 works through this in depth for essays. Biology's version is
narrower and the answer is firmer: **do not attempt to grade a written answer, and do not
imply that you have.** A student who writes a correct answer in unexpected words and is told
they are wrong will stop trusting the app, and they will be right to.

### 4.2 What to do instead: criteria self-marking

HSC Biology short answers are marked against **criteria points**, not against a model
paragraph. Mirror that:

1. The student writes their answer in a textarea. No live checking, no red squiggles.
2. On submit, reveal the marking criteria — one line per point the response needed — plus a
   sample answer.
3. The student ticks the points they actually made. That is the mark.

```js
{
  id: "sa-m7-014", mod: "M7", topic: "Immune response", marks: 4,
  q: "Explain how a vaccine produces long-term immunity to a specific pathogen.",
  criteria: [
    "Identifies that a vaccine contains an antigen from the pathogen (weakened, dead or a fragment)",
    "Describes the primary response: B lymphocytes are activated and produce antibodies",
    "States that memory B and T cells are produced and persist",
    "Explains that a later exposure triggers a faster, larger secondary response"
  ],
  sample: "A vaccine introduces an antigen …",
  common: ["Says the vaccine 'gives you the disease' rather than an antigen from it",
           "Describes antibodies persisting rather than memory cells"]
}
```

The `common` field is worth the extra minute per question: naming the mistake a student
probably made is the single most useful thing the feedback can do.

### 4.3 Keyword hints are allowed — as hints, labelled as hints

You may highlight which criteria *appear* to be addressed by matching a small synonym set
per criterion. This is genuinely useful for a student staring at four boxes wondering
whether they said the thing. It is **not** a mark, and the UI must say so in those words:
*"These look like they might be covered — you decide."* Never pre-tick a box, never colour
one red, never feed the keyword result into the score.

### 4.4 Self-marking is self-graded, so price it like flashcards

The chemistry app learned this: anything the student grades themselves is free XP unless it
is gated. Apply the flashcard rules (`MATHS-BRIEF-STANDARD.md` §9.8):

- A given short-answer question pays **once per day**, no matter how many times it is opened.
- It pays nothing if the textarea was empty or under about 20 characters.
- It pays nothing if the criteria were revealed in under `MIN_READ_MS` — nobody read the
  question that fast.
- Ticking every box on every question, every time, must earn **0 XP/hour** in `exploit.js`.
  Build that check the day you build the mode, not later.

## 5. Genetics — the one exactly-checkable part, so check it exactly

`js/core/genetics.js` is your physics-brief-style generator, and it must be verified the
same way (`PHYSICS-BRIEF.md` §5.2): compute the answer, then confirm it by a second,
independent route.

### 5.1 What it must handle

Monohybrid and dihybrid crosses; complete dominance, incomplete dominance and codominance;
sex linkage; multiple alleles (ABO); test crosses; and pedigree analysis.

### 5.2 The contract

```js
Genetics.cross({ mode: "dihybrid", parents: ["RrYy", "RrYy"] })
// → { grid: [...], genotypes: {RRYY:1, …}, phenotypes: {"round yellow":9, …},
//     ratio: "9:3:3:1" }
```

**Verify every generated cross two ways** across a few hundred seeds:

| Route A | Route B |
|---|---|
| Enumerate the Punnett grid and count | Multiply the independent single-locus probabilities |
| Phenotype ratio from the grid | The expected ratio for that inheritance pattern |
| Pedigree → inferred pattern | Simulate the stated pattern forward and check every individual is consistent |

That last one matters most. **A generated pedigree must have exactly one consistent
inheritance pattern**, or the question has no answer. Generate the pedigree from a known
pattern, then run your inference against *all* patterns and assert that only the intended
one survives. Any pedigree where two patterns both fit is discarded and regenerated. Without
this check you will ship pedigrees that are genuinely ambiguous, and a good student will
notice before your tests do.

### 5.3 Probability answers need a tolerance policy

"What is the probability the next child is affected?" has answers like ¼, 25%, 0.25 and
1 in 4. Accept all of them. The chemistry app's `U.parseNum` already handles most numeric
forms; extend it for `a/b` and `1 in n`, and unit-test the extension against a table.

## 6. Content — NSW HSC Biology

| | Module | Core topics |
|---|---|---|
| **Y11** | 1. Cells as the Basis of Life | cell structure, organelles, membrane transport, enzymes, respiration and photosynthesis |
| | 2. Organisation of Living Things | nutrient and gas exchange, transport in plants and animals, surface-area-to-volume |
| | 3. Biological Diversity | adaptation, theory of evolution by natural selection, evidence, biodiversity |
| | 4. Ecosystem Dynamics | past ecosystems, sampling and measuring, human impact, restoration |
| **Y12** | 5. Heredity | reproduction, cell replication, DNA and polypeptide synthesis, inheritance patterns, population genetics |
| | 6. Genetic Change | mutation, biotechnology, genetic technologies and their effects |
| | 7. Infectious Disease | pathogens, transmission, plant and animal responses, immunity, prevention and treatment |
| | 8. Non-infectious Disease and Disorders | homeostasis, causes of non-infectious disease, epidemiology, technologies and disorders |

### 6.1 Volume targets

| | target |
|---|---|
| Multiple choice | **120–180 per Y12 module, 80–120 per Y11 module** (~1,000 total) |
| Short answer with criteria (§4) | **150–220**, weighted to Y12 |
| Diagrams (§3) | **35–50** |
| Flashcards | **400–500** — more than any sibling app, see below |
| Genetics templates (§5) | **20–30**, each an unbounded family |

**Flashcards matter more here than anywhere else.** Biology's terminology load is enormous
and the spaced-repetition trainer is the single highest-value mode in the app for it. Budget
accordingly and weight it to definitions, processes and named examples.

### 6.2 Two accuracy rules specific to biology

**Every distractor needs a one-line reason it is wrong, stored with the question.** Biology
is full of options that are true statements but not answers to the question asked — "the
liver produces bile" is true under *"which of these is a function of the pancreas?"* only if
you were careless. Forcing yourself to write why each distractor is wrong is what catches
the ones that are secretly right. The validator should fail any question missing them.

**Build the distractor bank from named misconceptions**, as the physics brief does: teleology
("the plant wants more light"), Lamarckism ("the giraffe stretched its neck and passed it
on"), "survival of the fittest means the strongest", confusing correlation with causation in
epidemiology, antibiotics acting on viruses, "immunity" conflated with "vaccination",
mitosis/meiosis product counts, and dominant meaning "more common".

### 6.3 Validation

Everything from the chemistry validator applies — unique ids, four options, no duplicate
options, per-module answer-length bias under 36%, bigram near-duplicate detection. Plus:

- Every question has a `why`, and every distractor has its reason (§6.2).
- Every diagram part id in the data exists in the SVG string, and vice versa. A typo here
  produces a label that can never be placed, and nothing else notices.
- Every genetics template verified two ways over 200+ seeds (§5.2), and every generated
  pedigree checked for a unique consistent pattern.
- Every short-answer question has at least two criteria and a sample answer.

## 7. Modes, and the tool tray

### 7.1 The mapping

| Chemistry | Biology | Notes |
|---|---|---|
| Rapid Fire | **Rapid Fire** | 2 min, endless MCQ, streak multiplier to ×3 |
| Module Drill | **Module Drill** | 15 adaptive questions from one module |
| Balance Blitz | **Punnett Lab** | build the cross, predict the ratio — your flagship (§5) |
| Ion Memory | **Term Match** | term ↔ definition ↔ module, three-way |
| Name That Compound | **Label It** | the diagram engine (§3) |
| Calculation Crunch | **Data Detective** | read a graph or table and answer |
| Precipitation Panic | **Sort It** | classify against the clock: biotic/abiotic, mitosis stages, pathogen types |
| Titration Lab | **Pedigree Detective** | infer the inheritance pattern, then predict a cross (§5) |
| Pathway Puzzle | **Process Order** | sequence protein synthesis, the immune response, a reflex arc |
| Survival | **Survival** | one life, tightening clock |
| Mistake Rehab | **Mistake Rehab** | only what you've previously missed |
| — | **Response Builder** | the short-answer mode of §4 — new, and the most important |

**Read the addendum's §C1 and §C2 before building Process Order and Pedigree Detective.**
The chemistry Pathway Puzzle shipped two farming holes — a per-item score floor, and a
restart button that reset the cost counter — and both apply unchanged to any mode where you
can keep trying until it works.

### 7.2 The arcade

Three games you rent by the minute with the currency. **They pay nothing** — no XP, no
currency, no achievements, only a high score. An arcade game that paid XP would immediately
beat studying on XP per minute, which defeats the app. It is a *sink*, and the guarantee is
structural: arcade code never calls `UI.award`.

### 7.3 The tool tray

Copy `js/core/tools.js` wholesale. It docks a tray to the bottom of the screen in every game
with three tabs, and the chemistry app's version is worth reading for two fixes you would
otherwise rediscover:

- It **docks rather than floats**, and the view reserves the space it covers, so the question
  stays readable. The test measures that the question, the answer box and the submit button
  all sit clear of the tray rather than trusting the layout.
- The calculator display is `inputmode="none"` and its keys never call `focus()`. Focusing a
  text input is what makes a phone open its keyboard, and the first version popped the
  keyboard over the calculator on every key press.

Biology needs the calculator far less than chemistry did — magnification, surface-area-to-
volume, ratios and percentages, and that is about it. Keep it anyway; it costs nothing.
The **working space** matters more: genetics working and process sequencing both benefit.

**Pricing the reference.** In chemistry the data sheet is charged at −20% XP with a latch,
because the exam supplies a data sheet but not the solubility rules. Biology's exam supplies
nothing, so an in-app glossary during a scored run is a bigger crutch, not a smaller one.
Charge it at least as much, latch it on opening, and **withhold it entirely from Term Match
and Label It**, where the glossary and the diagram labels *are* the answer key. Chemistry hit
exactly this: the reference had to be withheld from Ion Memory and Precipitation Panic for
the same reason, because at −20% a perfect run using it still beat honest play.

## 8. Course coverage

Schools finish modules at different times, so a trial may not cover everything. Copy the
chemistry app's Settings → *Course coverage*: a set of switches that remove content from
every draw. Biology's obvious packs:

Year 11 as a whole; and within Year 12 — **biotechnology and genetic technologies** (M6),
**population genetics** (M5), **epidemiology** (M8), **homeostasis technologies and
disorders** (M8), **plant defences** (M7), and **evolutionary evidence** if your school
treats M3 as revision.

Two rules that make this safe rather than exploitable:

- Hiding content **never** raises what the remaining questions pay, and **never** lowers an
  achievement target. Otherwise switching topics off is the cheapest way to finish a
  collection — the same shape of mistake as a per-item score floor.
- The validator must check that every topic name, card id and module a pack claims actually
  exists. A typo hides nothing and is invisible from the app: the toggle still appears, still
  flips, and simply does nothing.

## 9. Progression and economy

Copy the chemistry numbers; they represent a year of tuning plus one explicit rebalance.

| | value |
|---|---|
| XP per correct answer | `10 × difficulty`, × streak multiplier (×1 → ×3 in half steps every 5 correct) |
| Level *n* cost | `round(115 × n^1.5)` XP, 60 levels |
| Lv 20 / Lv 60 total | ~77,000 / ~1.26 M XP |
| Currency payout | run value × **0.75** |
| Cheapest arcade ticket | ~315 for 5 minutes |
| Completion bonus | withheld entirely below 50% accuracy |
| Minimum read time | 1.2 s — faster than that earns nothing |

Retune them **together** and measure effort per purchase in units of "a run that nominally
pays 1000". Addendum §I has the before/after table from doing exactly that, and §B1 explains
why your first measurement will be wrong if you don't silence the other reward sources first.

## 10. Testing regime — build these as you go

Ten standalone Playwright/Node scripts. Retrofitting them is far more expensive.

1. **`validate.js`** — content integrity, no browser. Everything in §6.3.
2. **`smoke.js`** — every screen and mode driven end to end, zero console errors, no
   horizontal overflow at 360 and 390 px, hover states don't repaint primaries.
3. **`diagram.js`** — every diagram's part ids match its SVG; every hit area is ≥ 44 px;
   labels never overlap the artwork at 360 px.
4. **`genetics.js`** — every template verified two ways over 200+ seeds; every generated
   pedigree has exactly one consistent inheritance pattern.
5. **`exploit.js`** — a bot that plays every mode badly, including ticking every self-marking
   box. Target 0 XP/hour.
6. **`honest.js`** — a bot that plays every mode well. Comfortably higher, roughly consistent
   across modes.
7. **`tools.js`** — the tray never covers the question; the keypad never focuses the display.
8. **`coverage.js`** — every pack removes what it claims and grants no advantage.
9. **`offline.js`** — install, go offline, every screen renders, progress persists.
10. **`update.js`** — a deployed version is detected while open **and** applied on next
    launch. Run it with `BREAK=1` to confirm it still fails without the fix.

**And the habit that matters more than any of them: prove each test fails without its fix.**
Addendum §A. It caught three tests in the chemistry app that were passing while testing
nothing at all — including one where the assertion only checked a value wasn't *too small*,
so a bug that made it ten times too large sailed through.

## 11. The defects you are inheriting

Full detail is in the two maths documents. Skim now, read the detail when you reach the code.

**Silent failures** — you will not notice these without a test:
hand-listed content dropped 87 flashcards *(D4)*; a service worker cache version not bumped
means your fix never reaches an installed phone *(E1)*; an import destroyed itself because
`location.reload()` fired `pagehide`, flushing the old in-memory save over the imported file
*(F1)*; unigram duplicate detection passes exact opposites *(D2)*; a whole-bank
answer-length average hides one badly-authored module *(D1)*.

**Farming** — a student will find these:
per-item score floors *(C1)*; restart buttons that reset the cost counter *(C2)*; optional
helpers that refund their penalty when switched off *(C3)*; randomly generated boards that
come up trivially uniform *(C4)*. **Self-marked short answers belong on this list** — see
§4.4.

**Service worker** — the biggest source of support questions in the chemistry app:
`updatefound` never fires for an already-waiting worker *(E2)*; calling `update()` when one
is already waiting makes Chromium reinstall it and downgrades a silent apply into a
dismissable prompt *(E3)*; iOS does not clear website data when a home-screen PWA is deleted,
so ship a Force refresh and show the running build *(E6)*.

**Layout and input:**
`display:grid` beats the `hidden` attribute — add `[hidden]{display:none !important}`
*(maths §9.1)*; grid and flex children default to `min-width:auto` and overflow on mobile
*(§9.2)*; a hover rule that merely repeats a base value still outranks `.btn-primary`, giving
dark text on a dark fill *(H2)*; sticky elements must clear fixed chrome, so publish the bar
height as a CSS variable *(H3)*; a phone's decimal keypad has no minus sign and no exponent,
so any answer needing one must be enterable from on-screen controls.

**UX:**
never open a results overlay over an explanation the student is reading — gate it behind a
button and provide a way back *(H1)*. This matters more in biology than anywhere: your
sample answers and criteria lists are the longest explanations in the family.

## 13. Tone

The student using this is doing the HSC. It should feel like a game they *want* to open, not
homework with points bolted on. Every wrong answer is a teaching moment: say what the
misconception was, not just what the answer was — §6.2 gives you that for free.

And it must be **honest**. If it says a run is worth 200 XP, that is what a student who knows
the biology earns, and a student who knows nothing must earn zero. Just as important in this
subject: never tell a student their written answer is wrong. Show them the criteria, show
them a good answer, and let them judge. The moment the app pretends to mark prose it
cannot mark, they stop believing the parts it marks correctly.
